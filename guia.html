Blueprint do backend

Um diagrama navegável do backend de qualquer projeto, em qualquer stack: o modelo conceitual (o que existe e como se relaciona) com os fluxos de negócio desenhados por cima, passo a passo — num único HTML, com as cores do próprio projeto. Feito para que uma IA gere e para que o desenvolvedor entenda o sistema sem ler o código inteiro.

Exemplo

Loja Aurora, uma loja virtual fictícia

16 conceitos, 19 relações e 6 fluxos — com jobs, webhooks, uma variante e uma divergência entre o app e a API —, nas cores (também fictícias) da loja. Escolha um fluxo na lista e clique em Apresentar.

Fluxo “Confirmar o pagamento” destacado: números nas relações usadas, seta tracejada onde não há relação, o resto esmaecido. Abrir em tela cheia.
A ideia

Um modelo parado, fluxos que acendem o caminho

O ER mostra tabelas, mas esconde o gateway, a fila e quem aperta o botão. O diagrama de sequência mostra a ordem de um fluxo só. Aqui o mapa fica parado e cada fluxo acende o seu caminho nele — dá para ver que “Pedido” é tocado por seis fluxos diferentes.

Entidade

O que o backend guarda: tabela, coleção, agregado. Pedido, Produto, Conta.

Sistema

Com o que o backend conversa ou o que roda sozinho: gateway de pagamento, fila de jobs, e-mail, transportadora.

Ator

Quem age de fora: comprador, equipe de suporte, operador de caixa.

O passo de um fluxo

Uma interação de → para : ação — “Gateway → Pedido: confirma por webhook” — com as mudanças de estado (paid → refunded), as regras, as mensagens de erro reais e a fonte no código. Sem relação entre os dois conceitos, o passo vira uma seta tracejada — e isso já é informação.

Para a IA

Como a IA constrói

  1. Combina o escopo com o desenvolvedor: backend inteiro ou um recorte, e onde salvar (fora do repositório, por padrão).
  2. Levanta o backend: entidades no schema (Drizzle, Prisma, Django, Rails…), sistemas nas integrações, webhooks e jobs, atores nos papéis, fluxos nos casos de uso — sempre com o arquivo de origem. Guia.
  3. Escreve o blueprint.json e valida com node modelos/validar.mjs. Formato.
  4. Extrai as cores do projeto (tokens, Tailwind, CSS do painel, tema) para um tokens.css, com a origem de cada valor. Guia.
  5. Monta o HTML com node modelos/montar.mjs, abre e confere. Checklist.
  6. Entrega dizendo o que cobriu, o que ficou de fora e as divergências que achou no código.

Regra de ouro: fonte no código e nada inventado. Um diagrama bonito com regra falsa é pior que nenhum.

Formato

O blueprint.json

{
  "project":   { "name": "Loja Aurora — backend da loja virtual", "source": "loja-aurora · src/", "generatedAt": "2026-11-09", "locale": "pt-BR" },
  "concepts":  [ { "id": "ent_pedidos", "name": "Pedido", "code": "ORDERS", "kind": "entity", "description": "…" } ],
  "relations": [ { "id": "rel_12", "from": "ent_pagamentos", "to": "sys_gateway", "label": "é processado no" } ],
  "flows": [ {
    "id": "flw_confirmar", "name": "Confirmar o pagamento", "actor": "Gateway de pagamento (webhook)",
    "steps": [ {
      "title": "Receber o webhook", "from": "sys_gateway", "to": "ent_pagamentos", "action": "confirma por webhook",
      "changes": ["Pagamento: `pending → paid`"], "rules": ["…"], "errors": ["mensagem real do código"]
    } ]
  } ]
}

Detalhes campo a campo em referencia/02-modelo-json.md; schema formal em modelos/blueprint.schema.json. A interface sai em português ou inglês conforme project.locale ("pt-BR" ou "en").

Identidade visual

As cores do projeto, não as nossas

O visualizador só lê variáveis --bp-*. A IA procura as fontes de verdade do design do projeto e as traduz:

VariávelPapelOnde procurar
--bp-accentCor de ação: números dos passos, botão principalprimary, cor da marca
--bp-highlightAtivo/selecionado, ícone dos conceitosaccent, tom claro da marca
--bp-bg · --bp-surfaceFundo do diagrama · cartõesmuted/fundo de página · card
--bp-text · -soft · -faintTexto principal, de apoio, metadadoforeground, muted-foreground
--bp-edge · --bp-edge-strongRelações · caminho do fluxocor da marca e versão escura
--bp-font · --bp-radiusTipografia · formafont-family, --radius

Ordem de busca: arquivo de tokens → Tailwind → variáveis CSS do painel → tema da biblioteca de componentes → app mobile → documentação de design → logo. Guia completo em referencia/04-identidade-visual.md.
